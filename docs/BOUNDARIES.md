# 加载、配置和跨电脑能力边界

核对日期：2026-10-31。使用 OpenAI Docs 技能查阅官方资料；用户已确认的协作规则与产品能力说明分开保存。

## 官方资料支持的部分

- Codex 在会话开始时建立 AGENTS 指令链。它会考虑全局入口及项目根到当前目录的入口，近层优先；同层 AGENTS.override.md 优先。找不到项目根时只检查当前目录。默认合并大小上限为 32 KiB。因此，本包完整生成到实际入口，不把 Markdown 链接当自动 include。安装一个多项目容器的根入口，并不证明每个独立子仓库都加载它。来源：[AGENTS.md 官方说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。
- 配置是分层的，启动参数、可信项目层、所选 profile、用户设置等可能有不同优先级；组织要求还能约束设置。因此，复制 config.toml 或文本偏好不是实际生效证明。本包不自动修改这些配置。来源：[配置基础](https://learn.chatgpt.com/docs/config-file/config-basic)。
- 使用模型必须受当前账号/工作区支持；共享偏好不是另一个设备的可用性承诺。认证、通知和若干机器本地键不属于可用项目配置覆盖的范围。来源：[配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)。

## 客户端能力必须本机验证

不同客户端可能有不同的独立对话工具、模型、审批覆盖和通知行为。创建路径与旧会话权限不能互相推断；只有新会话实际上下文及无副作用验证才能证明本次有效。这里不附带任何个人电脑的版本、路径、线程或实际配置。

普通过程保持安静；每项派发任务结束时，依用户直接授权发送一次不超过 40 字的可见状态标记，主对话主动读取结果、验收并汇报。静默内部消息仍不保证唤醒已结束回合的主对话；漏通知的任务在后续交互或已配置日程中主动补查。在目标客户端验证出其他机制前，不承诺即时静默唤醒或持久后台运行。

## 脚本证明什么

workflow.py 只管理文件：生成共同规则区块、保留本机内容、备份、校验版本和检测手改。它不创建模型调用、对话、权限、Git 远端、日程或后台服务。status 一致也不能证明模型刚刚加载了入口。

目标客户端须通过受支持的新会话实际列出来源核验。已有更深层项目规则、全局覆盖、长度上限或客户端能力都可能影响结果。skill 可以承载可按需调用的操作，但本任务的长期默认行为更适合 AGENTS 入口，因此没有额外安装 skill。
