# 迁移到 1.1.0

适用于首次启用和已有 1.0.0 工作区。无需重新安装账号、复制聊天或改全局配置；公司电脑的原有规则和个人电脑的规则不会互相上传。

## 已有 1.0.0

1. 执行对话先读取当前 TASK/最新派单，再确认本机规则包来源、工作树和版本。安全同步规则源，保留本地未提交改动；只更新当前目标，不递归扫描/安装全部项目。
2. 使用本机可用 Python 对同一目标运行 `workflow.py install --workspace <目标>` 预览，确认管理区块外原文保留。无真实语义冲突则按既有授权加 `--apply`；本轮另有冻结/审查要求时先遵守。
3. `.assistant-workflow/local.json` 的已有模型、私有未知字段、线程及调度归属继续保留；缺少的 `test_device_policy` 自动补为 `simulator-only`。配置 schema 仍为 1，无须删除状态或用示例覆盖。
4. 运行 `status` 核对文件，再用受支持的新会话核实实际加载、目录、模型和权限。未在该电脑验证的能力标为未验证，不把临时目录测试说成双机部署完成。

已手改管理区块、丢状态、入口改变或确有行为冲突时，保留差异并按 SYNC.md 合并，不删除状态绕过保护。原始备份保留在本机忽略目录。

## 新字段与行为

| 字段/约定 | 默认或变化 | 是否跨机复制 |
| --- | --- | --- |
| `test_device_policy` | `simulator-only`：只使用模拟器，真机项目记未验证 | 本机选择，不直接复制 local.json |
| `task-authorized` 可选值 | 仍默认模拟器，真机须本次明确用户授权；不能自动放宽既有“只用模拟器”限制 | 同上 |
| 当前 TASK 与检查点 | 当前派单优先于旧聊天、fork 历史和压缩摘要 | 原始任务留本机/项目 |
| 私有收取台账 | 保存实际对话、来源、产物、验收和已告知证据 | 否 |
| 纯回执 | 无需执行、改文件或再次通知；不形成新任务 | 只共享这一通用规则 |

需要调整测试设备偏好时，由用户明确选择后只编辑本机字段，再预览、应用生成区块；不要直接手改管理区块。此字段不能授予业务权限。规则更新不创建日程、转移调度归属或自动推送项目资料。

## 首次启用与后续改进

首次启用直接按 README 单条指令及 START_HERE.md；已有电脑按上述流程更新。后续任一电脑产生好方法，确认通用性、去掉公司/个人细节后更新 COMMON.md、VERSION 和 CHANGELOG.md，在已有仓库授权内提交；另一台下次安全同步并安装。没有自动双向同步或会话热重载。
