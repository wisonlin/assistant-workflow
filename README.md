# Assistant Workflow

可跨电脑复用的主对话与独立执行对话协作模板。

一次接入后，由一个主对话协调、独立执行对话完成具体工作；共同方式可通过 Git 迭代，各电脑保留自己的目录、认证、权限与日程。本包不内置后台服务，不搬运聊天或账号状态。默认普通过程安静；每项派发任务结束时，只在用户授权内发一次不超过 40 字的状态标记，详细报告留执行端。主对话负责读取、验收、汇报，未通知的任务也要在后续活跃回合主动收取。短标记仍会可见，不能承诺即时又隐藏。

## 另一台电脑怎么接入

把本目录复制过去，或以后克隆共享仓库。在目标工作目录打开 Codex，对它说一条：

> 请读取你能访问的 assistant-workflow/START_HERE.md，按其中流程把这套协作规则接入当前工作目录；保留已有规则，核实实际加载与能力，然后告诉我能直接使用的范围。

如果包不在当前目录，只需给出 START_HERE.md 的实际路径；不需要重新讲协作历史。包内 [START_HERE.md](START_HERE.md) 是完整的一次接入入口。

## 共同维护什么

| 内容 | 位置 | 是否共享 |
| --- | --- | --- |
| 已确认的协作方式 | [rules/COMMON.md](rules/COMMON.md) | 是，唯一可编辑规则源 |
| 版本与来源 | [VERSION](VERSION)、[CHANGELOG.md](CHANGELOG.md) | 是 |
| 工作目录、设备名、实际能力与调度归属 | 目标工作区 `.assistant-workflow/local.json` | 否 |
| 原有项目规则 | 目标 AGENTS 管理区块外 | 沿用该项目的公开范围 |
| 私有补充、当前任务、认证、聊天、自动化 ID | 本机私有目录；local.md 按需读取 | 否 |

安装工具把共同规则完整写入目标实际 AGENTS 入口的受管理区块，不依赖“链接到另一个文件会自动加载”。区块之外逐字保留，安装前显示差异，并留本机备份。生成区块不含真实路径、设备名或私有 local.md 内容；本机状态目录自身带全忽略规则，避免被目标项目普通 Git 提交带上。既有 AGENTS 内容的公开范围仍由该项目自行管理。它不修改全局 Codex 设置、不创建日程、不自动获取或授予权限。

## 安装与更新

需要 Python 3.9+；无需安装第三方依赖。先由执行对话探测本机条件，再执行：

```sh
python3 assistant-workflow/workflow.py install --workspace /目标工作目录
python3 assistant-workflow/workflow.py install --workspace /目标工作目录 --apply
python3 assistant-workflow/workflow.py status --workspace /目标工作目录
```

第一条只预览；第二条在已有接入授权下应用；第三条报告文件层状态，不冒充模型实际加载证明。Windows 可将 `python3` 换成已探测到的 `py -3` 或 `python`，路径用参数传递。

模型、思考强度和语言是本机可配字段；示例默认为 `gpt-6.1-sol / xhigh` 和中文，必须核实账号与客户端实际支持。规则升级后用同样命令更新。管理区块被手改或状态不一致时工具会拒绝覆盖，并显示差异，交给执行对话合并。目标存在非空 AGENTS.override.md 时采用该实际优先入口；空 override 与非空 AGENTS 并存会停止，避免启用新 override 后遮蔽旧规则。已安装后入口变化也会停止并要求核对。

独立子仓库不保证加载外层工作根规则。对要直接启动新会话的子项目，执行者应对该子项目再安装一次，或采用已核实会保留规则的同目录 fork。不要递归改写全部历史项目。

## 两边怎么一起改进

公开上游用于通用方法和经过脱敏的改进；个人私密偏好可放独立私有派生仓库，两台各有一个 clone，按 [同步与改进流程](docs/SYNC.md) 合并。只同步规则包，不把整个工作根目录纳入一个仓库。

也可以直接复制文件夹接入；自动双向更新需要自行配置远端与更新流程。Git 同步文本不等于客户端权限、会话或日程已生效。
