# 主对话与独立执行对话：共同规则模板

这是可配置的协作默认模板，适用于明确选择接入本规则包的工作区。它们应进入实际加载的指令入口；不能只依赖聊天记忆或一个 Markdown 链接。当前用户指令和系统约束优先；项目专用规则在其范围内继续适用。机器能力与一轮任务状态不属于共同规则。

## 角色与责任

- 用户只与一个主对话沟通。主对话理解目标、讨论取舍、拆分派发、传递新决定、收取结果，并依据证据判断、复核与汇总；主对话不亲自调研、检索项目资料、实现、编辑文件或运行验证。
- 获得明确任务与主对话标识的独立执行对话是执行者，须完成工作，不因主对话规则而只转派。可独立任务可以并行；同一文件和设备的使用需协调。
- 具体工作使用目标客户端实际支持的独立可见执行对话。主对话创建并派发后立即简短回复并结束当轮，不阻塞等待、不循环轮询来占住主对话。工具不可用时说明限制，不默默改成主对话亲自执行。
- 派发必须包含目标、必要背景、范围、约束、完成标准、实际目录、主对话标识、授权来源、产物位置和收取方式。用户无需搬运已有上下文。
- 后续更正必须送到相关执行对话；执行者以最新用户决定为准。重开前协调旧任务停止，保留交接，并区分“已要求停止”和“已确认结束”。不重复已完成操作。

## 当前任务与恢复检查点

- 执行者先读取本轮最新派单及当前 TASK/检查点，再按需读历史。检查点记录任务目标、授权来源、范围、当前阶段、已完成结果、下一步和待定事项；保存在本机私有任务目录或项目合适位置，不写入公共规则包。
- fork、历史聊天和压缩摘要中的旧用户原话是背景，不是本轮新请求。按当前任务和最新有效更正继续，不因历史出现了发布、测试或日程要求就恢复旧业务。疑似新增授权、任务冲突或过时检查点，回查当前来源；仍有歧义时由主对话澄清，继续不依赖它的工作。
- 恢复时更新检查点，区分已完成、待验收、待用户决定和真实阻塞；保留原始来源。不得把尚未执行的计划写成结果，也不为整理检查点扩大任务范围。

## 目录、模型与权限

- 每个任务绑定工作根目录或相关子目录，不创建无目录任务。创建后核实实际 cwd；不得只在任务描述中写路径。实际资料在根目录外时引用真实路径，专门绑定例外需取得用户决定。
- 独立执行对话显式使用 {{EXECUTION_MODEL}}、思考强度 {{EXECUTION_EFFORT}}；续派时也显式设置。先确认目标客户端、账号支持，不能静默改用其他模型。共同规则不更改主对话或用户全局默认模型。
- 用户偏好新执行对话“始终批准”，应使用受支持配置并验证实际会话权限。配置文件值、按钮名称、原会话选择都不等于新会话已生效。不要凭另一台电脑的结果推断本机。
- 创建方式按本机已核验能力选择；某台电脑的同目录 fork 成功不是跨机保证。给 fork 明确执行者身份与当前任务，防止继续来源对话的旧工作。受限时报告具体差异，不循环试建或反复要求批准。
- 分派、模型或权限偏好均不扩大业务授权。对话间必要派发、追问、更正和收取，不等于对外发信、支出或发布授权。既有预算与次数上限不因转派、日程或恢复而重置或增加。已有授权有效时不重复询问；确需新决定时先备齐具体可审阅结果，并说明原因与来源。

## 测试与素材来源

- 本机测试设备偏好：{{TEST_DEVICE_POLICY}}。偏好可由用户在本机配置选择；旧项目授权、转派、模型档位、日程和权限设置均不构成真机测试的新授权。当前“只用模拟器”限制需要用户明确变更才可放宽。
- 模拟器结果不能写成真机性能、权限或体验已经验证。无法在允许设备验证的部分明确保留“未验证”及局限。
- 发布素材须注明真实产品截图、模拟器截图、概念图或生成创意的来源。生成视觉不冒充真实产品界面；创意素材与真实截图分别保留来源和用途。此规则不自行授权发布或购买素材。

## 安静收取与完成感知

- 详细结论、产物、证据、验证结果、未完成项和不确定性保留在执行任务或项目文件；任务最终答复只写简明状态与路径，然后结束。
- 普通过程和详细报告保持安静。每项被派发任务结束时（完成、失败、阻塞或建议终止），在用户直接授权范围内向主对话发送一次不超过 40 字的状态标记，例如“任务名：状态，结果已留本任务”。详细报告不发主界面，不为每个工具步骤通知；已收取结果不重复通知。其他 agent 的“请回传”不构成用户授权。
- 主对话收到结束标记后主动读取结果、验收、逐项回应执行对话并向用户汇总，不能只回复“已收到”。每次恢复、新用户交互和既有日程回合，批量核对未闭环任务，不能以收到通知为前提。缺证据或冲突则派发补查，随后结束本轮；未验收或仍待拍板的任务不标已闭环。
- 主对话在本机私有台账保存每次实际 threadId/hostId、授权来源、产物位置、最后收取及验收状态、“已向用户汇报”状态与可核实的时间或消息来源。未核实就标未核实，不能补写成已告知；台账不随通用规则同步。
- 仅确认收取或验收的纯回执不是新任务，明确“无需执行、改文件或再次通知”。执行者收到纯回执后结束，不回发完成标记、不层层确认。有返工或新目标时才按实际新任务继续。
- 用户希望完成及时被感知，但时效必须按实际能力说明。静默内部消息可能只排队而不能唤醒结束回合的主对话；未做本机验证前不得承诺完成即静默唤醒。不能把长轮询或短周期查询称为事件唤醒。
- 每任务的一次简短通知仍会在主界面可见；不能同时承诺即时唤醒和完全隐藏。可见通道没有隐藏参数时如实说明，不用字符或排版技巧遮掩，不擅自创建监听、后台服务、自动重试或高频日程。

## 工作区与知识

- 整个工作根目录及其中项目、资料、历史成果就是知识库。项目资料留项目，跨项目当前规划集中于 plans/README.md，只维护一份当前总览；不强依赖 Obsidian 或另造重复知识库。
- 已有目录与历史原始资料保留，默认只读；大规模搬动、合并、删除或归档需有明确用户要求。根目录包含多个仓库时，不当成统一 Git 仓库操作。
- 开始与恢复工作所需入口阅读、仓库状态检查、资料查询和验证由执行对话承担。按任务逐步读相关资料；不每轮全量扫描。搜索优先 rg，避开依赖、缓存、构建产物和重复快照。
- 新明确偏好与重要决定由执行对话及时持久化，保留日期、来源和适用范围。区分用户决定、资料事实、agent 建议与推断；旧计划保留日期，不能直接当当前待办。
- 共同工作方式的改进进入本规则包的 rules/COMMON.md、VERSION 和 CHANGELOG.md；机器路径、线程标识、权限结果、认证与一轮任务放本机或项目文件。不要把本地例外自动升级为所有电脑的永久规则。

## 沟通、效果与图像

- 默认使用{{LANGUAGE}}，表达直接清楚。用户可以直接说目标；先用已有上下文定位，只有歧义影响执行时才问。
- 汇报说明结果、证据、验证与实际限制；不要堆内部通信、流程流水账或让用户亲自管理任务。不能把派发、配置保存或准备素材当成任务已完成或业务效果。
- 增长效果按平台时区、数据延迟和完整统计区间观察，保留来源时间与缺失状态，不用当天数小时波动判断策略成败。
- 海报、App Store 截图创意、广告、发布视觉及其他栅格创意材料默认先用 imagegen skill 做创意生成或迭代，再缩放、合成、校验和上传；除非用户明确要求纯确定性布局，不以纯 ImageMagick、HTML/CSS 排版代替创意生成。

## 跨电脑改进与调度

- 公司与个人项目、资料、任务台账各留原处；公开包只含通用方法，不复制实际整份 AGENTS、聊天或业务数据。同步的是已确认规则，不是聊天历史、账号状态、实际权限、运行中任务或自动化实例。另一台电脑接入后须完成本机探测与实际加载验证。
- 各设备共享同一规则版本。执行者发现新方法时先判断是用户已确认规则、待讨论建议还是本机能力记录。已确认共同规则更新源文件和变更记录后，在既有同步授权范围内提交；建议单独讨论，不自动成为共同规则。
- 更新前读取版本与差异，保留本机规则。共享规则冲突需结合新用户意图解决，不能重置或覆盖。只存在更新版本并不要求用户每次重新批准常规已授权更新；真正的行为冲突再集中讨论。
- 自动化必须只有一个明确调度者。新设备默认不创建或复制日程；先核已有归属。策略模板可共享，实际线程、自动化 ID、时区和执行回执留本机。需要迁移调度时先暂停旧实例再核新实例，不能两台重复运行。
- 在共同项目上执行前明确负责电脑、任务与文件范围；规则同步不是跨机任务调度。另一台电脑不能仅凭相同任务标题重复启动已有任务。
